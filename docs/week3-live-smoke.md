# 3주차: 실제 시스템 제어기 시험 실행

실행일: 2026-11-20. 시뮬레이터와 같은 `capacity.Controller` 를 실제 docker 시스템에 붙여 15분간 돌렸다.

```bash
WORK_MICROS_PER_TX=10000 scripts/reset.sh 0
python3 -m controller.main --policy proposed --duration 900 --speedup 10 --boot-median 30 \
    --trace-start-h 321.33 --log data/live/smoke-proposed.csv
python3 scripts/load.py --rate 1.8 --duration 780        # 다른 터미널
```

| 항목 | 값 |
| --- | --- |
| 부하 | 초당 1.8건(포아송), 13분, 작업 1,383건 (작업당 약 2초) |
| 회수 | AWS 4노드 us-west-2c trace 를 10배속 재생. 약 4분 시점에 스팟 6대 회수 (첫 4대 전부 + 새로 뜬 워커 일부) |
| 부팅 지연 | 로그정규 중앙값 30초 + 실제 JVM 기동 |
| 제어기 반응 | 회수 직후 적체 97건 → 스팟 5대 + 온디맨드 4대로 증설, 다음 주기(90초 안)에 적체 0 |
| 완료시간 | 평균 9.1초, p99 64.2초, 최대 66.6초. 목표(5분) 위반 0건 |
| 대사 | 1,383건 모두 확정, 유실·중복·금액 불일치 0 (PASS) |

관찰:
- f_p 가 1.0(이 trace 구간은 "전부 회수"가 잦음)이라 제안 기법이 온디맨드 4대를 섞었다. 시뮬레이터 결과(회수 집중에서 온디맨드 대체)와 같은 동작이다.
- 적체가 사라진 뒤에도 축소 지연(10분) 때문에 9대를 유지했다. 짧은 실행이라 축소까지 보지 못했다. GameDay 에서는 30분 이상 돌린다.
- 측정한 Tready q95 가 사전값 64초에서 86초로 갱신되었다. 실제 기동 시간이 추정에 반영되는 것을 확인했다.
