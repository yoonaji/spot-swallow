- 발생 / 감지 / 복구 시각 (KST): 20:45:10 / 20:45:20 / 20:45:32 (복구 선언 20:48:48, 다른 장애가 없는지 3분 더 관찰)

- 현상: 대사 결과가 `consistent: false`, `amountMismatch: 1` 로 바뀜. 큐, DLQ, 워커 수, API 는 정상. Grafana "대사 불일치 발생" 알림은
  울리기 전(규칙 감지에 약 21초 걸림)에 복구가 끝나 pending 에도 가지 않음
- 영향: 가맹점 M0001, 2026-01-01 정산 1건의 총액·정산금이 +1.00원. 지연된 작업 0건, 완료시간 목표 위반 0건, 유실·이중 확정 0건
- 원인: 확정된 결과 테이블을 앱을 거치지 않고 직접 수정 (주입기의 "원장 변조"). 워커가 확정할 때 남긴 `COMPLETED` 이벤트의 net 값은 정상이었다

- 조치: 결과 1건을 입력 거래로 다시 계산한 값으로 수정, 수정 이력을 `job_events` 에 남김
- 재발 방지:
  1. **결과 테이블에 직접 UPDATE 가 가능하다.** 지금은 대사로 사후에 잡을 뿐이다. 워커 DB 계정에서 UPDATE·DELETE 권한을 빼고,
     정정은 별도 계정과 이력 테이블로만 하게 한다. 이력은 append-only 감사 로그로 남긴다 (플랜의 보안 항목과 연결).
  2. **누가 바꿨는지 모른다.** DB 감사 로그가 없어 "앱 밖 변경"까지만 판단했다. 같은 감사 로그로 해결한다.
  3. 알림보다 대사 API 를 직접 본 쪽이 11초 빨랐다. 알림 규칙의 평가 주기(10초)와 지표 수집(15초 주기 게이지)이 감지의 하한이다.
     돈이 틀린 장애는 대사 주기를 줄이는 것이 MTTD 를 줄이는 방법이다.
- 잘한 점: 공통 원칙 1(돈이 틀렸는지 먼저)대로 대사를 먼저 봐서 바로 잡았다. 이벤트 이력으로 워커 버그와 외부 변경을 구분했다.
- 막힌 점 / 도구 문제: GameDay 주입기가 주입이 끝난 뒤 기록 파일을 다시 저장하면서 대응자가 남긴 감지 시각을 덮어썼다.
  감지 시각은 대응 로그에서 복원했고, 주입기는 주입 직전에만 저장하도록 고쳤다.
- 한계: 대응자가 장애 후보 4종과 런북을 미리 알고 있었다. 사람이 대응하는 회차와 비교해야 MTTD/MTTR 의 의미가 생긴다.
